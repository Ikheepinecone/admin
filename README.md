# Package.mgl — packaging e-commerce front-end

A complete browse-and-order storefront for paper bags, boxes and wrapping paper.
Built with **HTML5, Tailwind CSS and vanilla JavaScript** — no framework, no build step needed to run it.

Mongolian is the default language; visitors can switch to English (MN/EN toggle in the header).

## Run it

Open `public/index.html` in a browser — it works straight from the file system.
For a local server (recommended, closer to production):

```bash
npm run serve        # or: cd public && python3 -m http.server 8080
```

The compiled stylesheet `public/assets/css/styles.css` is included. Rebuild it only after changing classes:

```bash
npm install
npm run build        # one-off, minified
npm run dev          # watch mode while editing
```

## What's in it

| Page | What the customer can do |
|---|---|
| `index.html` | Hero with real die sizes drawn to scale, “What are you packing?” size finder, categories, most-ordered products, how ordering works, custom-size inquiry, about + contact |
| `products.html` | Browse by category (with counts), search (name, die code, or `32x12`), filter by colour, stock and **item to fit (L × W × H)**, sort, switch between product cards and the full **All sizes** price list, add sizes to compare |
| `product.html?id=…` | 3D / front / next-to-A4 drawings with dimensions, size picker, paper weight, colour, quantity (MOQ + step enforced), live volume pricing, total, add to cart / order now, size guide, specs, all sizes & prices, related products |
| `compare.html` | Up to 4 sizes side by side, drawn to the same scale next to an A4 sheet, with a spec table |
| `cart.html` | Change size, paper weight, colour and quantity per line; remove with undo; free-delivery progress |
| `checkout.html` | One page: contact → delivery or pickup (UB districts) → e-receipt (individual / organisation reg. no.) → payment (bank transfer, QPay invoice, cash). Guest checkout, optional account creation, confirmation with order number |
| `account.html` | Email sign-up / log-in, order history with details and one-click **Order again** |
| `contact.html` | Validated inquiry form with topic, confirmation message, direct contact details |

## Updating products, sizes, prices and photos

**Dies / sizes** — `public/assets/js/data/templates.js` is a direct transcription of the spreadsheet
(`Хэвний нэр`, `Өндөр`, `Урт`, `Өргөн`, `Формат`). Add or edit one row per die.

**Products** — `public/assets/js/data/catalog.js`. Each product lists its sizes either by die code
(`'T001'`) or as explicit objects (`{ code, l, w, h, price }`). The header comment in that file documents
every field: colours, paper weights (GSM), MOQ, quantity step, unit, etc.

**Prices**
- Die-based sizes: `unit price = pricing.base + flat-blank area (m²) × pricing.perM2`, at the product's
  `gsmDefault`. Heavier/lighter paper adjusts the price proportionally.
- Explicit sizes: set `price` on the size object; it overrides the formula.
- Volume discounts: `PK.CONFIG.priceTiers` in `config.js` (now 5% from 500, 10% from 1,000, 15% from 3,000).

**Photos** — the site draws every product from its real dimensions, so it looks complete without photos.
To use real photography (recommended), save images in `public/assets/img/products/` and list them on the product:

```js
images: ['assets/img/products/twisted-white-1.jpg', 'assets/img/products/twisted-white-2.jpg'],
```

The first photo replaces the drawing on product cards; all photos appear as extra views on the product page.
Photos on a plain white or light-grey background blend best with the grey product tiles.

## Before going live

1. **Replace placeholders in `public/assets/js/config.js`**: phone, email, address, map link, opening hours, legal name.
2. **Review the sample data** in `catalog.js` — everything marked `sample: true` (boxes, wrapping papers,
   and the size lists for flat-handle and no-handle bags) is realistic placeholder data. Prices are estimates.
3. **Connect a back-end.** By default orders, accounts and messages are stored in the visitor's browser
   (demo mode). To receive them:
   - Quick: set `endpoints.order` and `endpoints.contact` in `config.js` to a URL that accepts a JSON `POST`
     (your API, or a form service). The full order/inquiry object is sent.
   - Full: replace the functions in `public/assets/js/core/store.js` (`auth.*`, `orders.*`) with calls to your API.
     Pages only talk to that module. Real authentication must be done server-side.
4. **Translations**: all interface text is in `public/assets/js/core/i18n.js`; product text is in `catalog.js`.
   Please have the Mongolian copy proofread.

## Assumptions to confirm

- Spreadsheet note **`hiih`** (T006, T022, T025) is read as “die still to be made” → shown as **Made to order**
  with a 7–10 day lead time. Change `status` logic in `public/assets/js/core/shop.js` if it means something else.
- **`bantiktai tor`** (T026, no width) → flat ribbon-tie gift bag; **`tsonkhtoi`** (T032) → small bag with window.
- **`Формат`** is shown as the flat blank (unfolded sheet) size.
- T006 has no format recorded; its price uses an estimated blank size.

## Admin dashboard (`/admin.html`)

Open `admin.html` (on Vercel: `https://your-site.vercel.app/admin.html`). Demo sign-in: **admin@demo.mn / admin123**.

| Section | What it does |
|---|---|
| Overview | Revenue, orders, average order and new customers vs the previous 7 / 30 / 90 days; revenue chart (with table view); best sellers; sales by category; low-stock alerts; recent orders |
| Products | Search, filter, sort; create, edit, duplicate, show/hide, delete (with undo); bulk actions; live storefront preview while editing |
| Inventory | Stock per size × colour, low/out-of-stock tabs, inline edits (with undo), bulk restock, CSV export. At 0 the store shows the size as "Made to order"; every order reduces stock |
| Orders | Status tabs, search, one-click next step (New → Confirmed → Paid → Shipped → Completed), cancel, internal notes, CSV export |
| Customers | Everyone who ordered or signed up: contact details, orders, total spent, order history, CSV export |
| Messages | Contact-form inbox with unread state and reply by email |
| Settings | Download `catalog.js` to publish product changes, remove/add sample data, restore defaults, language |

**How the data works today:** the admin and the store share the browser's storage, so everything works
end-to-end on one computer. Sample orders and messages are generated the first time the admin opens so the
charts have something to show (Settings → *Remove sample data*).

**Publishing product changes without a server:** edit products in the admin → Settings → *Download
catalog.js* → on GitHub replace `public/assets/js/data/catalog.js` with it → Vercel redeploys.

**Before real use:** the demo sign-in is not security, and orders placed by customers stay in *their* browsers.
To run the shop for real, connect a database with sign-in (e.g. Supabase). Only `public/assets/js/admin/data.js`
and `public/assets/js/core/store.js` talk to storage, so those are the two files to change.

## Deploy to Vercel (no terminal needed)

1. **GitHub**: create a free account at github.com → **New repository** (e.g. `package-mgl`, Private) →
   on the empty repository page click **uploading an existing file** → drag in *everything inside* this
   project folder (`public`, `src`, `tools`, `package.json`, `package-lock.json`, `tailwind.config.js`,
   `vercel.json`, `README.md`) → **Commit changes**.
2. **Vercel**: sign up at vercel.com with **Continue with GitHub** → **Add New… → Project** → **Import** the
   repository → leave all settings as they are (`vercel.json` already tells Vercel what to do) → **Deploy**.
3. After about a minute you get a live address like `https://package-mgl.vercel.app`.
4. **Updates**: change or re-upload files on GitHub → Vercel publishes the new version automatically.
5. **Own domain**: Vercel project → **Settings → Domains** → add your domain and copy the DNS records it
   shows into your domain registrar's settings.

Vercel's free *Hobby* plan is meant for personal, non-commercial projects; a company store should use a paid
plan (check vercel.com/pricing) or a host whose free tier allows commercial use.

## Editing page markup

The eight HTML pages share one shell generated by `tools/build-pages.py` (header/footer are injected by
`layout.js`). Either edit the page bodies in that script and run `python3 tools/build-pages.py`, or edit
the HTML files directly and stop using the script.
